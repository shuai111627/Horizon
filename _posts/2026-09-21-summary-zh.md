Simon Willison 发布 llm-keys-ui 0.1，这是其 llm CLI 的一个插件，用于在一台机器上启动本地 Web 界面，以便把 API 密钥写入该机器，而不必把密钥粘贴进代理会话。作者的使用场景是：他通过 Codex Remote 从手机控制多台机器上的编码代理，需要用密钥时让代理执行 \`uvx --with llm-keys-ui llm keys-ui --all\`，命令会返回若干可访问的 URL（包括局域网或 Tailscale 设备 IP），在浏览器界面中保存密钥；之后可用类似 \`llm keys get anthropic\` 的命令在 shell 中取用。文章配图显示界面列出 anthropic、openai、openrouter、qwen-dummy 四个已存密钥名，表单提供 Key name 与 New value 字段和 Save key 按钮，且已有密钥的值不会被显示。该版本号为 0.1。

rss · Simon Willison · 9月20日 19:22

**「为何现在值得注意」** 材料显示这是一个刚发布的 0.1 版本插件，针对的是“在远程机器上配置 LLM 项目所需 API 密钥时不希望把密钥直接粘进代理对话”这一具体约束。除作者本人的工作流说明外，材料没有提供采用情况、后续计划或更广泛影响，因此它更像是对既有 llm CLI 生态的一个小补充，而非平台或产品层面的变化。

**「内容角度」** 可做角度：从“不把 API 密钥粘贴进 AI 代理会话”这一具体约束出发，梳理远程或手机端控制编码代理时密钥分发这一环节的实际做法——本地 Web 界面负责写入、CLI 负责读取，并如实说明它的前提（需要能访问到该机器，文中给出的地址形式包括局域网与 Tailscale 设备 IP）。
